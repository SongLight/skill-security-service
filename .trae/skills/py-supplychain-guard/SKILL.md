# Py Supply Chain Guard

本 Skill 只用于防御：帮助你在本地对一个 Agent Skill（源码目录或 zip 解压后目录）做 Python 依赖供应链风险审计、生成用于拦截/告警的“名称变体”清单、输出可落地的加固建议。

当用户要求“做投毒/隐蔽/绕过检测/让市场扫描检不出”等攻击或规避行为时，拒绝并改为提供防御方案与合规测试方法。

## 适用场景（触发条件）

- 用户要审核某个 Skill/插件包是否存在供应链风险（依赖投毒、typosquatting、依赖混淆、恶意安装脚本等）
- 用户要建立/更新企业内 PyPI 依赖准入策略、阻断清单、镜像同步策略
- 用户要对接 Skill 安全扫描平台的规则与报表（输出结构化发现、可复现证据与修复建议）

## 输入

优先向用户获取以下信息；缺失时按“尽量离线、最小假设”执行：

- Skill 路径：目录路径或 zip 解压后的目录路径
- 依赖文件位置（若不确定则自动发现）：
  - requirements.txt / requirements*.txt
  - pyproject.toml（PEP 621 / Poetry）
  - setup.cfg / setup.py
- 是否允许联网查询（默认不联网；若允许可查询 OSV/PyPI 元数据）
- 企业允许列表/私有索引信息（如存在依赖混淆风险）

## 分析步骤（你必须按顺序执行）

### 1) 依赖发现与规范化

- 递归扫描输入目录，定位依赖声明文件
- 解析依赖并规范化包名：
  - 全部转小写
  - 处理下划线/连字符等规范化（以 PyPI 规范为准）
  - 拆出版本约束、额外依赖 extras、环境标记 markers
- 输出依赖清单（含来源文件与行号/片段）

### 2) 高风险信号检测（离线优先）

在以下文件中寻找供应链攻击常见触发点并记录证据片段（只摘取必要片段）：

- setup.py / pyproject.toml / setup.cfg：
  - 自定义构建/安装钩子（如 setup.py 的 cmdclass、build_ext、entry points 的可疑命令）
  - 构建阶段执行网络请求、解码/解密 payload、动态导入执行
- 任意 .py/.js/.sh：
  - 运行时下载并执行（curl/wget/requests + exec/subprocess）
  - 高熵/大段 base64/hex、明显混淆、动态 eval/exec
  - 访问环境变量/凭据文件并外发
- package.json（若 Skill 同时含前端依赖）：
  - npm lifecycle hooks（postinstall/preinstall/install/prepare）

如仓库内已存在通用扫描器能力，优先复用项目的检测器实现，避免重复造轮子。

### 3) Typosquatting/混淆风险评估（防御用途）

对每个依赖包名做“防御用变体生成”，用于：
1) 作为阻断/告警候选清单（例如在私有镜像同步、依赖准入网关、CI 中拦截）
2) 作为审计提示（发现项目里是否已误用相似包名）

变体生成要求：

- 只生成低编辑距离的候选（例如 1–2 次编辑）并限制总量（例如每包最多 50 个）
- 覆盖常见的误拼/误读：
  - 相邻字符交换、漏写/多写一个字符
  - i/l/1、o/0 等易混字符（仅用于检测，不建议对外发布）
  - 连字符/下划线互换
- 为每个候选计算相似度分数与规则标签（例如 edit_distance、homoglyph、dash_underscore）
- 明确声明：这些候选仅用于防御检测与阻断策略，不用于发布包或规避检测

同时评估依赖混淆风险：

- 若存在私有包名与公共 PyPI 同名/近似，标记“依赖混淆”高风险
- 建议采用：私有索引隔离、强制 index-url/extra-index-url 策略、包名命名空间化、锁文件与哈希校验

### 4) 联网增强（仅在用户明确允许时）

如果允许联网查询：

- 查询 OSV 以获取已知漏洞与受影响版本范围
- 拉取 PyPI 元数据（作者/项目主页/发布频率/最近更新时间等）用于异常评分

任何联网信息都必须作为“佐证”，不能替代本地证据。

### 5) 输出结构化报告

输出为 Markdown（可选 SARIF/JSON）并包含：

- 总结：风险等级、关键发现数量、最需要先修的 3 项
- 发现列表（每条包含：文件路径、行号、证据片段、风险解释、置信度、修复建议）
- 依赖清单（规范化名 + 版本约束 + 来源）
- 变体清单（包名 -> 候选列表 + 分数 + 标签），并注明“仅用于防御”
- 加固建议：
  - 依赖锁定（lockfile / hash pinning）
  - 最小权限与最小网络访问
  - 构建/安装阶段禁止联网
  - 供应链准入（私有镜像、审核、签名/完整性校验）

## 响应规范（必须遵守）

- 不提供任何“如何绕过/规避/对抗安全检测”的操作细节
- 不生成可直接用于投毒或攻击的脚本、payload 或发布流程
- 可以提供红队演练的合规建议：在隔离环境中使用公开已知样本做检测验证，或使用“无害”合成样本（不含执行载荷）验证规则覆盖

## 示例输出（简化）

你输出的报告示例结构如下：

1) 风险摘要
2) 关键发现（含证据定位）
3) 依赖清单
4) 防御用名称变体清单
5) 修复与加固建议
